------------------------------------------------------------------------------
1. PROJE NEDİR?
------------------------------------------------------------------------------

ADS Guardian, bir web sunucusuna gelen HTTP trafiğini gerçek zamanlı olarak
izleyen ve saldırıları otomatik olarak tespit eden bir siber güvenlik sistemidir.

Sistem Docker üzerinde çalışan bir nginx web sunucusunun loglarını anlık olarak
okur ve şu saldırı türlerini tespit eder:

  - DoS (Denial of Service / Hizmet Engelleme): Sunucuyu çok sayıda istekle
    bunaltmaya çalışan saldırılar. Makine öğrenmesi (Random Forest) ile tespit edilir.

  - Brute Force (Kaba Kuvvet): /login, /admin gibi hassas sayfalara tekrarlı
    giriş denemesi yapan saldırılar. Kural tabanlı skor sistemiyle tespit edilir.

  - SQL Injection: URL parametrelerine "UNION SELECT", "DROP TABLE" gibi
    zararlı SQL komutları yerleştiren saldırılar. Regex + anomali skoru ile tespit edilir.

  - MITM (Man-in-the-Middle): Henüz implement edilmemiş, placeholder olarak
    sistemde kayıtlı duruyor.

Sistem iki farklı arayüz sunar:
  a) Terminal modu (detect.py): Renkli terminal çıktısıyla anlık alarm basar.
  b) Web dashboard (dashboard.py): Tarayıcıda gerçek zamanlı grafik ve tablo gösterir.

──────────────────────────────────────────────────────────────────────────────
DOSYA: detect.py
──────────────────────────────────────────────────────────────────────────────
AMAÇ: Terminal modunda gerçek zamanlı saldırı tespit döngüsü.
      Web arayüzü olmadan, saf terminal çıktısıyla çalışır.

NASIL ÇALIŞIR:
  1. Docker SDK ile belirtilen container'a bağlanır
  2. Tüm kayıtlı dedektörleri yükler
  3. Arka planda bir thread başlatır: SESSION_TIMEOUT_SECONDS (20 sn) boyunca
     log gelmeyen IP'lerin saldırısının bittiğini ilan eder
  4. Container log akışını okur, script başladıktan SONRA gelen logları işler
     (geçmiş logları atlar)
  5. Logları 50'lik batch'ler halinde işler (performans için)
  6. Her batch için tüm aktif dedektörleri çalıştırır
  7. Saldırı tespit edilirse 15 saniyelik cooldown ile alarm basar
     (aynı IP için tekrarlı alarm bastırır)

ALARM ÇIKTISI:
  - 🔴 KRİTİK: Güven skoru > %80
  - 🟡 UYARI : Güven skoru %55-80 arası
  - Saldırı bitince özet rapor gösterir (süre, toplam istek, pik RPM)

ÖNEMLİ DEĞİŞKENLER:
  _attack_sessions : IP → oturum bilgisi (başlangıç zamanı, toplam istek, vb.)
  _flagged_ips     : Şu an saldırı altında olan IP seti
  ALERT_COOLDOWN_SECONDS = 15  (aynı IP için alarmlar arası minimum süre)
  SESSION_TIMEOUT_SECONDS = 20 (bu kadar süre log gelmeyince saldırı bitti sayılır)

PARAMETRELER:
  --container : Docker container adı (varsayılan: "hedef-sunucu")

──────────────────────────────────────────────────────────────────────────────
DOSYA: dashboard.py
──────────────────────────────────────────────────────────────────────────────
AMAÇ: Web tabanlı gerçek zamanlı güvenlik dashboard'unun backend'i.
      Flask web framework + Flask-SocketIO ile yazılmıştır.

NASIL ÇALIŞIR:
  4 ayrı arka plan thread paralel çalışır:

  Thread 1 — _log_reader_thread:
    Docker container loglarını okur, her satırı _process_line() ile işler.
    Container bulunmazsa 5 saniye bekleyip tekrar dener.

  Thread 2 — _socketio_emitter_thread:
    _event_queue kuyruğundan event alır, bağlı tüm tarayıcılara Socket.IO
    ile push eder. Bu sayede tarayıcı sayfayı yenilemeden veriyi alır.

  Thread 3 — _cleanup_expired_sessions:
    Her 5 saniyede bir aktif saldırı oturumlarını kontrol eder.
    SESSION_TIMEOUT_SEC (30 sn) boyunca log gelmeyen IP'leri temizler.

  Thread 4 — _uptime_thread:
    Her saniye sistemi çalışma süresini günceller ve tarayıcıya gönderir.

_process_line() FONKSİYONU (tek bir log satırını işler):
  1. feature_extractor ile log satırını parse eder
  2. Tüm dedektörleri sırayla çalıştırır
  3. Saldırı tespit edilirse _event_queue'ya "attack" event'i koyar
  4. Her log satırı için _event_queue'ya "log" event'i koyar
  5. Dakika bazlı zaman serisini (_timeseries) günceller

PAYLAŞILAN VERİ YAPILARI (thread-safe, _lock ile korunan):
  _stats             : Toplam istek, saldırı, parse hatası sayıları
  _attack_type_counts: Saldırı türü → kaç tane tespit edildi
  _recent_logs       : Son 500 log satırı (ring buffer)
  _attack_sessions   : Aktif saldırı oturumları (IP → oturum bilgisi)
  _recent_attacks    : Son 100 saldırı kaydı
  _timeseries        : Son 60 dakikanın istek/saldırı zaman serisi

REST API ENDPOINTLERİ:
  GET /              → Dashboard HTML sayfasını döner
  GET /api/stats     → İstatistikler, aktif saldırılar, zaman serisi
  GET /api/logs      → Son log satırları
  GET /api/attacks   → Son tespit edilen saldırılar
  GET /api/detectors → Yüklü dedektör listesi
  GET /api/health    → Sistem sağlık durumu

SOCKET.IO EVENTLERİ (backend → tarayıcı):
  "init"    → Tarayıcı bağlandığında mevcut tüm veriyi gönderir
  "log"     → Yeni log satırı
  "attack"  → Yeni saldırı tespiti
  "uptime"  → Her saniye çalışma süresi
  "system"  → Sistem mesajları (hata vb.)

PARAMETRELER:
  --container : Docker container adı (varsayılan: "hedef-sunucu")
  --port      : Flask portu (varsayılan: 5000)
  --host      : Dinleme adresi (varsayılan: 0.0.0.0 = tüm arayüzler)

──────────────────────────────────────────────────────────────────────────────
DOSYA: detector/feature_extractor.py
──────────────────────────────────────────────────────────────────────────────
AMAÇ: Ham nginx log satırını makine öğrenmesi modelinin anlayabileceği
      sayısal özellik vektörüne dönüştürür.

NGINX LOG FORMATI (combined):
  192.168.1.1 - - [01/Jan/2026:12:00:00 +0000] "GET /index.html HTTP/1.1"
  200 1234 "-" "Mozilla/5.0..." 0.023

parse_log_line() FONKSİYONU:
  Regex ile log satırını parçalar ve şu sözlüğü üretir:
    ip                       : Kaynak IP adresi ("192.168.1.1")
    path                     : İstenen URL yolu ("/index.html")
    method                   : HTTP metodu ("GET", "POST" vb.)
    requests_per_ip_last_60s : Kayan pencere — o IP'nin son 60 sn istek sayısı
    bytes_sent               : Yanıt boyutu (byte)
    status_code              : HTTP durum kodu (200, 404 vb.)
    method_encoded           : Metod sayısal kodlaması
    path_depth               : URL derinliği
    user_agent_length        : User-Agent uzunluğu
    response_time_ms         : Yanıt süresi (milisaniye)
    sqli_keyword_score       : SQL anahtar kelime skoru (0.0-1.0)
    sqli_char_score          : Tehlikeli karakter skoru (0.0-1.0)
    sqli_pattern_score       : Regex örüntü skoru (0.0-1.0)
    sqli_anomaly_score       : Toplam SQLi anomali skoru (0.0-1.0)
    sqli_matched_count       : Eşleşen kural sayısı

KAYAN PENCERE (Sliding Window):
  Her IP için son 60 saniyedeki tüm istek zamanları bir deque'da tutulur.
  Her yeni istekte 60 saniyeden eski kayıtlar silinir.
  Bu sayede "son dakikada kaç istek" bilgisi her an güncel tutulur.

SQLi SKORING MOTORU (compute_sqli_scores):
  3 katmanlı scoring:
    1. Anahtar kelime skoru: "union"(0.35), "drop"(0.40), "xp_cmdshell"(0.50)
       gibi SQL anahtar kelimeleri URL'de var mı?
    2. Karakter skoru: %27 (tek tırnak), %3B (noktalı virgül) gibi
       URL-encoded tehlikeli karakterler var mı?
    3. Regex örüntü skoru: "UNION SELECT"(0.90), ";DROP TABLE"(0.90),
       "SLEEP("(0.85) gibi bilinen saldırı örüntüleri var mı?
  Toplam anomali skoru: pattern*0.60 + keyword*0.25 + char*0.15

──────────────────────────────────────────────────────────────────────────────
DOSYA: detector/attacks/brute_force.py
──────────────────────────────────────────────────────────────────────────────
AMAÇ: Kural tabanlı skor sistemiyle brute force saldırısı tespit eder.
      Makine öğrenmesi kullanmaz, deterministik kurallara dayanır.

PUANLAMA SİSTEMİ (toplam puan >= 0.50 ise saldırı):
  +0.30 → HTTP durum kodu 401 veya 403 (kimlik doğrulama hatası)
  +0.25 → Hassas path: /login, /admin, /wp-login.php, /api/auth vb.
  +0.25 → Son 60 sn'de aynı IP'den >20 istek (yüksek frekans)
  +0.10 → Son 60 sn'de aynı IP'den 10-20 istek (orta frekans)
  +0.10 → HTTP metodu POST (giriş formları POST kullanır)
  +0.10 → User-Agent uzunluğu <20 karakter (botlar kısa UA gönderir)

ÖRNEK: Bir IP /login'e saniyede 5 kez POST ile 401 alıyorsa:
  401 kodu (+0.30) + hassas path (+0.25) + yüksek frekans (+0.25) +
  POST (+0.10) = 0.90 → SALDIRI (eşik 0.50'nin çok üstünde)

──────────────────────────────────────────────────────────────────────────────
DOSYA: detector/attacks/sql_injection.py
──────────────────────────────────────────────────────────────────────────────
AMAÇ: İki katmanlı yaklaşımla SQL Injection saldırısı tespit eder.

KATMAN 1 — Kritik örüntü regex (anlık, hızlı):
  Şu örüntülerden biri eşleşirse anında saldırı → güven: %95
    - UNION SELECT (veya UNION ALL SELECT)
    - ;DROP / ;INSERT / ;UPDATE / ;DELETE
    - SLEEP( veya WAITFOR DELAY(
    - information_schema.
    - xp_cmdshell
    - LOAD_FILE(
    - INTO OUTFILE

KATMAN 2 — Orta riskli örüntü regex:
  2 veya daha fazlası eşleşirse saldırı:
    - OR x=x (mantıksal enjeksiyon)
    - AND x=x
    - /* ... */ veya -- (yorum enjeksiyonu)
    - 0x... (hex kodlama bypass)
    - (SELECT ... (subquery)

KATMAN 3 — Anomali skoru (feature_extractor'dan):
  sqli_anomaly_score >= 0.50 ise saldırı

URL DECODE: Saldırılar genelde URL-encoded gelir (%27 = ').
  Hem ham hem decode edilmiş hali kontrol edilir.

explain() metodu: Saldırı kararının tam açıklamasını döner
  (debugging ve dashboard için kullanılabilir).

5. GENİŞLETME — YENİ SALDIRI TİPİ EKLEME
------------------------------------------------------------------------------

Sisteme yeni bir saldırı tipi eklemek son derece basittir:

  1. detector/attacks/yeni_tip.py dosyası oluştur
  2. Şu şablonu kullan:

     from detector.base_attack import BaseAttackDetector
     from detector.attack_registry import register

     @register
     class YeniTipDetector(BaseAttackDetector):
         name = "yeni_tip"

         def detect(self, features: dict) -> bool:
             # Buraya tespit mantığı
             return features["requests_per_ip_last_60s"] > 200

         def confidence(self, features: dict) -> float:
             # 0.0 - 1.0 arası güven skoru
             return min(features["requests_per_ip_last_60s"] / 500, 1.0)

  3. Başka hiçbir dosyaya dokunmaya gerek yok.
     attack_registry.py klasörü otomatik tarar ve dedektörü yükler.
